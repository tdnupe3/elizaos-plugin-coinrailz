Publicly Accessible AI Agents Supporting A2A

Agent-to-Agent (A2A) is an open protocol (launched April 2025 by Google and partners) that enables AI agents to directly communicate and collaborate across different vendors and frameworks
developers.googleblog.com
thelogic.co
. Below, we’ve compiled a comprehensive list of publicly accessible agents (including enterprise, domain-specific, and research/demo agents) that already support A2A or can use it, organized by domain.

Developer-Oriented and Research Agents

LangGraph and LangChain Agents – LangChain (popular Python framework for LLM apps) and its multi-agent extension LangGraph have added support for A2A. In fact, the LangChain docs describe how a LangGraph-based agent can expose an A2A endpoint

. An example is the LangGraph Currency Conversion Agent – a demo agent that converses about currency exchange and provides real-time rates. It was built with Google’s Gemini LLM and LangGraph, and exposes a standard A2A API (with a public .well-known/agent.json describing its capabilities)
a2aprotocol.ai
a2aprotocol.ai
. This agent supports streaming responses and multi-turn dialogue, and demonstrates how a LangGraph agent can be “called” by other agents needing currency info

a2aprotocol.ai
. For instance, a travel agent could A2A-call the Currency Agent to convert prices. (The agent’s card shows it offers a convert_currency skill and requires no auth for public use

crewAI Agents – crewAI is an open-source framework focusing on orchestrating multiple role-based agents. It has A2A support and sample agents. One highlight is the CrewAI Image Generation Agent, which can create or edit images from natural language prompts
google-a2a.wiki
. This agent uses A2A’s binary file transfer (the FilePart in messages) to send image data as artifacts
google-a2a.wiki
google-a2a.wiki
. For example, you can send it a request to "generate a chart from data X" and it will return an image file artifact. Another crewAI demo (from Google’s codelab) is a pair of Burger Ordering Agent and Pizza Ordering Agent: two separate services that use A2A to negotiate a combined meal order (illustrating inter-agent delegation in a retail scenario)
codelabs.developers.google.com
. These are more for demonstration but are publicly documented for developers to try. They show how one agent can discover another via its agent card and then invoke it as a sub-task – e.g. a “BurgerAgent” might call “PizzaAgent” to also order a side pizza for a combo deal.

Google ADK Sample Agents – Google’s open-source Agent Development Kit (ADK) provides reference A2A agents in Python. One example is the Expense Reimbursement Agent (built with ADK) that handles employee expense reports – it can receive a receipt (image/PDF), OCR it, categorize the expense, and apply company policy rules

. It streams status updates and returns the final artifact (e.g. a completed expense form) via A2A. Another is the “Hello World” agent in ADK tutorials, which simply echos greetings but illustrates the agent card structure and A2A messaging. These are more proofs-of-concept, but they are publicly accessible on GitHub and can be run and exposed as A2A endpoints for testing

Other Open-Source Multi-Agent Projects – A number of community projects have adopted A2A to let agents built in different frameworks interoperate:

Semantic Kernel / AutoGen (by Microsoft) – These are libraries for creating multi-agent systems (AutoGen enables GPT-4 agents to converse). With A2A, an AutoGen agent could interface with an external tool-agent instead of only local tools. Microsoft even showcased an AgentFactory pattern where an agent built with Semantic Kernel calls another built with LangChain over A2A
azure.microsoft.com
azure.microsoft.com
. This means you can mix and match frameworks.

BeeAI (IBM Research) – It originally had its own protocol (ACP), but now there’s community effort to bridge BeeAI agents with A2A. This would allow, say, an AutoGPT (autonomous GPT agent) to talk to a BeeAI contract-analysis agent through an A2A gateway.

Academic demos: Many academic or hobby projects are standing up simple agents with an A2A interface – e.g. a SQL query agent that others can call for database questions
a2aprotocol.ai
, or an email-sending agent that handles notifications. These might be listed on community sites like the A2A Agent List or GitHub’s awesome-a2a repository
google-a2a.wiki
github.com
. While not all are production-grade, they show the growing variety of tasks being agentified.

Multi-Agent Simulations – Research demos like agent societies (e.g. Stanford’s Generative Agents town simulation) are also exploring A2A. For example, one could wrap each simulated agent with an A2A server, enabling external interaction or modular replacement. This is theoretical, but as A2A matures, even research agents (in games, simulations, etc.) can be made “publicly accessible” for others to plug in. The Linux Foundation now hosts the A2A spec, so we anticipate open innovation – everything from smart home agents to game NPC agents could expose A2A endpoints for interoperability.

In summary, there are already dozens of AI agents across domains supporting A2A, from enterprise assistants like Rovo and SAP Joule, to finance bots like QuickBooks’ agents and PayPal’s payment agent, to content and dev-focused agents like Box’s document agent and LangGraph demos. The common thread is that each exposes a standard interface (an Agent Card at /.well-known/agent.json and JSON-RPC endpoints) so that any other agent can discover its capabilities and converse with it securely

cloud.google.com
. This growing interoperability means we can mix-and-match agents to build complex multi-agent workflows. For example, a user’s request could trigger a chain: a planning agent delegates to a specialist agent (via A2A) and maybe to another, and so on, until the task is done

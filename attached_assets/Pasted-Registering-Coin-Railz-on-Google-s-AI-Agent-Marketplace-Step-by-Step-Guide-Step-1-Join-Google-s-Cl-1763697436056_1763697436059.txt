Step 2: Gather Required Assets and Documentation

Prepare Your Agent Manifests and Credentials: Before creating the listing, compile all the necessary assets for Coin Railz. Key requirements include:

Agent Card JSON: Google’s AI Agent Marketplace relies on the Agent2Agent (A2A) Agent Card, which is a JSON metadata file describing your agent. Coin Railz already hosts a discovery manifest at /.well-known/agent-card.json – ensure this file adheres to the latest A2A specification (the Marketplace expects it in the standard format). The Agent Card is essentially the agent’s “digital business card,” containing its name, description, version, capabilities (skills), endpoints (API URLs), supported input/output formats, and any auth requirements
eco.com
. It defines the agent’s presence on the marketplace and facilitates interoperability with other agents
docs.cloud.google.com
. Verify that Coin Railz’s agent-card JSON is up to date (Coin Railz is A2A v0.3 certified; update the protocolVersion if needed to match the latest spec, e.g. v1.0). You will use this Agent Card in the listing process (Google can ingest the agent’s metadata directly from this JSON
cloud.google.com
).

OpenAPI Specification: Coin Railz also provides an OpenAPI document at /.well-known/openapi.json. Prepare this API specification as it documents the agent’s endpoints and capabilities. While not always a formal requirement for listing, including an OpenAPI spec is highly useful for developer discoverability. It can be referenced in your listing or documentation to show developers how to integrate with Coin Railz’s APIs. Make sure the OpenAPI spec is comprehensive and reflects all the services (including any micropayment endpoints).

x402 Payment Protocol Manifest: Coin Railz supports the Agent2Agent x402 protocol, enabling autonomous micropayments using USDC across 7 blockchains. Gather any manifest or documentation you have for this (e.g. /.well-known/x402.json if provided). This shows how Coin Railz handles the HTTP 402-based payment flows. Highlighting x402 support is a strong differentiator – x402 is an extension that converges Google’s A2A communication with Coinbase’s 402-payment standard, allowing AI agents to seamlessly handle stablecoin transactions in their interactions
eco.com
. Ensure you have documentation on the 18 microservices Coin Railz offers via x402 (e.g. payment APIs, pricing per call, supported chains) as this can be included in your listing or attachments.

Branding and Visuals: Prepare your agent’s branding assets. At minimum, you’ll need an icon or logo for Coin Railz to display on the Marketplace. Google may accept a URL to the icon (your Agent Card can include an iconUrl field) or require uploading an image. Use a square image (PNG/SVG) that represents Coin Railz. Additionally, gather any screenshots or diagrams that explain your agent (if relevant), though for AI agents the primary representation is typically the JSON metadata and description rather than UI screenshots.

Support Documentation: Have a brief user guide or documentation page ready (you can host this on coinrailz.com/docs or similar). In the Marketplace listing, you’ll provide links for customers to learn more or get support. Ensure you have a support email or contact prepared, as Google will ask for how customers can reach you for troubleshooting. If Coin Railz has SLA or support offerings, document those as well.

Credentials for Integration: Because Coin Railz will be offered as a SaaS-style service, you’ll need to integrate with Google’s billing and identity systems. Prepare to set up OAuth 2.0 credentials on Google Cloud (for enabling “Sign in with Google” on your platform) – this will involve using the Google Cloud Console to create an OAuth client ID for a Web Application (with redirect URIs provided by Google)

If usage-based pricing is planned, you may later need to set up service accounts to report usage metrics, but for now just be aware of these technical needs.

By assembling these assets up front – the Agent Card JSON (capabilities manifest), OpenAPI file, payment/x402 details, logos, and integration credentials – you will streamline the listing process. Google’s Marketplace team will review many of these items, so having them polished and readily accessible is crucial.

Product Information: Enter the basic details of your agent. This includes the product name (e.g. “Coin Railz – Autonomous Micropayments Agent”), a short description, and categories/tags. Choose a clear, professional name that reflects the agent’s function. The short description should immediately signal the value (e.g. “An A2A-certified AI agent enabling autonomous USDC micropayments across multiple blockchains”). This is what users see in search results, so include keywords like “A2A protocol”, “Gemini Enterprise”, “x402 payments” to improve discoverability by developers and enterprises.

Listing Ownership: Ensure the correct Google Cloud project and organization are associated with the listing in the portal (usually, your Partner Advantage organization and the project created for Marketplace). This ties the listing to your company’s account for management and billing. If prompted to enable any APIs (such as the Cloud Commerce Partner Procurement API), do so in this step – these APIs allow Google to handle billing and notify your system of purchases.

Google has made onboarding AI agents straightforward by leveraging the Agent Card. In fact, the Marketplace supports ingesting your agent’s metadata automatically from the Agent Card JSON to save time
cloud.google.com
. In the portal, you will likely be asked to provide your Agent Card. You can supply the URL to the agent-card.json (which Coin Railz publishes at https://coinrailz.com/.well-known/agent-card.json) or upload the JSON file. Once provided, Google’s system will parse it to pre-fill many fields (like the agent’s name, version, description, capabilities, endpoints). This simplifies the process and ensures consistency – the data in your Agent Card becomes the source of truth for the marketplace listing

Pro Tip: Before submitting the Agent Card in the portal, validate it against the official A2A schema. Since Coin Railz has a 5/5 A2A compliance rating, your agent-card should already be well-formed. In summary, starting the listing is done in the Producer Portal by creating a new AI agent product. Use the Agent Card link to accelerate setup. Once initiated, you can proceed to fill in the details and configurations in subsequent steps.

Step 5: Set Pricing and Complete Technical Integration

Choose a Pricing Model: Next, decide how you want to monetize Coin Railz via the Marketplace. Google Cloud Marketplace for AI agents supports multiple pricing models
docs.cloud.google.com
, similar to SaaS products:

Free: Customers pay nothing to you for the agent itself (they would only incur Google Cloud usage charges, if any). This model maximizes adoption – it could be suitable if Coin Railz plans to monetize indirectly or if you want to remove any friction for initial users. If Coin Railz is in an early stage or focused on growth, free might attract more developers.

Subscription: A fixed monthly fee for using the agent
docs.cloud.google.com
. This gives predictable revenue. You could offer tiers (if the marketplace allows) or a flat rate for enterprise access to the micropayment agent. Ensure the value proposition is clear if charging a subscription – e.g. unlimited transactions up to certain limits, premium support, etc.

Usage-Based: Charge per use or according to metrics
docs.cloud.google.com
. For Coin Railz, a natural metric might be number of payment transactions executed, or volume of USDC transacted, or API calls made. Google allows custom metrics reporting if you choose usage-based pricing, but you will need to integrate metering and reporting to Google’s billing system. For example, you might charge $X per 100 micropayment operations. If you go this route, be prepared to instrument your platform to measure usage and send reports to Google (via the Marketplace usage reporting API). Usage-based pricing can align well with the micropayment nature of Coin Railz, but it requires more integration effort.

Combined (Subscription + Usage): A smaller base subscription plus overage fees for high usage
docs.cloud.google.com
. This could be viable if you want a guaranteed monthly baseline and also charge for heavy use. For instance, $100/month plus $0.01 per payment transaction beyond some included amount.

Select the model that fits your business. All pricing models that involve charges will be billed through Google Cloud to the customer, with Google then remitting your share (minus their fee). Set a fair price; consider offering a free trial or a low introductory price to encourage adoption, since this is a new marketplace. You will configure the pricing details in the Producer Portal (currency, price, metrics, etc.). After submission, Google will review your pricing plan, which can take up to four business days
docs.cloud.google.com
. They verify it aligns with their policies and that metrics make sense. You can continue other onboarding steps while waiting for pricing approval.

Usage Reporting (if applicable): If you chose a usage-based or hybrid pricing model, implement the usage metering. Ensure your system can tag and tally usage per Google customer account (Google will provide you a consumer ID or similar in the purchase event to identify the customer in reports). For a straightforward subscription model, usage reporting is not needed.

docs.cloud.google.com

Coin Railz being “fully production-ready” is a big advantage here – likely you already have robust account management and APIs, so adding Google OAuth and tying in the billing events will be relatively straightforward. Allocate time for development and testing of these integration points. Step 6: Submit for Review and Approval

Undergo Google’s Review Process: After filling in all details, uploading the Agent Card, setting pricing, and completing integration steps in the Producer Portal, you will formally submit the Coin Railz listing for Google’s review. Ensure your .well-known/agent.json or any discovery endpoints are live and correct. Google might also verify the agent can be added to a Gemini Enterprise environment without errors. Any issues found (like missing fields or unreachable endpoints) will be communicated back to you to fix.

Content Review: Google’s team will review the product description, marketing claims, and overall listing content for compliance with their policies (no prohibited content, no unrealistic claims, etc.). Pricing Review: If not already approved, they will finalize the pricing model review. This includes checking that any usage metrics are set up correctly. Timeline Expectations: The review process is iterative. Google’s team typically responds with initial feedback within a week or two. Since AI Agents on the Marketplace is a relatively new program (as of 2025), they may work closely with you (via email or through the Partner Portal feedback) to get everything in order. Each time you submit a section (like product details or integration), the portal will show it as “In Review”. The pricing review was already noted (4 business days average)

In total, expect a few weeks from initial submission to final approval, factoring in back-and-forth. Google’s goal is to ensure high-quality listings, so they will work with you on any required modifications.

Once all parts of the listing are approved, Google will give the green light. At that point, you can hit the “Publish” button in Producer Portal. Publishing is instantaneous after approval – the product page will go live on the Marketplace within minutes

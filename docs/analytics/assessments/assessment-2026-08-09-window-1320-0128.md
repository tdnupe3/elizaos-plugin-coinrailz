## 7. Security / Technical Issues

### MCP 402 Not Fully Machine-Payable (MEDIUM — conversion blocker)
`mcpDeliveryRoutes.ts` returns HTTP 402 with `error.code:402` and payment instructions pointing to x402.json, but does not emit a standard x402 `PAYMENT-REQUIRED` header/payload. An MCP client using standard x402 retry logic cannot automatically construct payment and retry. The first real tools/call hit this wall. Fix: ensure MCP 402 responses include the same machine-readable payment requirement header (`X-PAYMENT-REQUIRED` or equivalent) and a direct recipe endpoint reference that an x402-aware client can act on without a separate discovery step.

### Tencent Cloud Distributed Probe (LOW — recurring, no escalation)
Same Tencent Cloud (43.x.x.x) fake iPhone UA pattern from prior windows. One service per IP, staggered. No escalation. Ongoing; apply ASN-level rate limits when capacity allows.

### Unpaid POST flood — no rate limiting yet (LOW — cost efficiency)
74.220.48.55: 20 POSTs this window. IPv6 agent: 73 POSTs across 3 burst cycles. Each generates a DB write. No 429 response in place for repeated unpaid POST actors. Architect recommended per-IP budget with exponential backoff; still not implemented.

### PHP/WordPress probes (LOW — no action needed)
`/.well-known/pki-validation/*.php` and similar paths continue from generic vulnerability scanners. All return 404. No PHP runtime. No action required.

### Satellite API discovery note
`/api/satellite/*` getting 8–9 unique IPs per service directly. Architect confirmed these are properly x402-gated via `satellitePaymentMiddleware`. These hits return 402, not free data. No leak.

## 5. Impact of Recent Updates / Fixes

### Task #94 — facilitator field in accepts[]

**What changed:** All 402 responses now carry `facilitator: getFacilitatorUrl()` on every Base USDC and Base USDT `accepts[]` entry. Previously these fields were missing; the top-level `facilitatorUrl` was not sufficient for the Cloudflare Agents SDK.

**Evidence it's live:** IPv6 agent received the new 402 body at 03:57 and 14:05 UTC. The body is structurally correct.

**Evidence it's working:** No evidence yet. The agent received the correct body and did not attempt payment. This could mean: (a) it's not in a payment-attempt phase yet, (b) it still lacks USDC on Base, (c) it needs an additional trigger (e.g. a task instruction). 14 hours is too short to conclude the fix failed.

**Evidence it's not blocking:** No 500s, no malformed 402s, no errors in error table from this fix.

### Task #95 — HEAD-visible payment headers + execution_guide

**What changed:** 5 new headers on all 402 responses (X-Payment-Price, X-Payment-Network, X-Request-Example, X-Payment-Recipe-URL, X-Trial-Access). execution_guide injected into all 402 bodies.

**Evidence it's live:** Headers confirmed on fleet-telematics and related services in pre-deploy e2e tests.

**What worked:** execution_guide is now universally present. X-Request-Example provides correct POST body schema.

**What did not improve (architect-confirmed defect):** `X-Payment-Recipe-URL` points to the paid service endpoint (`/x402/{service}`). A GET there returns another 402. An agent following this header to get a recipe gets stuck. This header is currently misleading rather than helpful. Fix: deploy a dedicated unauthenticated `/x402/recipes/{service}` endpoint.

**Earthdata payer response:** The payer returned, but on multi-chain-balance (not fleet-telematics where the header is most relevant). It did 3 HEAD probes — the new headers were visible. No paid POST yet.

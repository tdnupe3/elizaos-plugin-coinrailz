What to probe / criteria to confirm “A2A compatibility”
When you find a candidate agent (or someone says “my agent is A2A-ready”), confirm via:

Agent Card: The agent should advertise a JSON “Agent Card” (name, version, endpoint, supported modalities, etc.). That is part of how A2A discovery works.

Protocol support: The agent’s endpoint should support JSON-RPC over HTTP(S), SSE (server-sent events) or gRPC push mechanisms, as defined in A2A spec.

Task lifecycle / states: The agent should accept tasks with a lifecycle (submitted, working, completed, failed) rather than just one-shot requests.

Security/auth: The agent should support authentication/authorization (e.g. via OAuth, signed agent cards, tokens) as per the spec.

Streaming / artifact parts: If the agent supports output parts (text, files, structured JSON, images) or streaming, that is evidence of more full A2A support.

Inter-agent delegation: Ideally, the agent itself may call other agents in an A2A fashion — that demonstrates that it is fully built in the A2A paradigm.

🔹 OpenAI and A2A
OpenAI is not currently part of the A2A initiative.
At launch (April 2025), Google announced A2A with partners like Microsoft, Salesforce, SAP, Box, ServiceNow, Atlassian, PayPal, Intuit, etc. — OpenAI was not listed .

ChatGPT / GPTs don’t natively expose an A2A agent card or JSON-RPC interface. Instead, OpenAI offers the Assistants API (REST) and “GPTs” via the GPT Store. Both are OpenAI-proprietary, not A2A-compliant.

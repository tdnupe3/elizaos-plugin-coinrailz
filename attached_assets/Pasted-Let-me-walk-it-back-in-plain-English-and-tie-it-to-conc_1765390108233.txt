2. The npm package (coinrailz)
What it is (mechanically)

A JavaScript/TypeScript client library published to npm:

npm install coinrailz


Developers do:

import { CoinRailzClient } from 'coinrailz';

const client = new CoinRailzClient({ apiKey: 'YOUR_API_KEY' });

const gas = await client.gasPriceOracle({ chain: 'base' });
const signals = await client.tradeSignals({ token: 'ETH' });
const wallet = await client.createAgentWallet({ description: 'bot-wallet-1' });


Under the hood it:

Calls your /x402/... endpoints

Uses API keys / prepaid credits, not USDC/x402 directly

Handles errors, timeouts, typing, etc.

What changed in the world because of this

Before:

Anyone wanting to use Coin Railz had to:

Read your docs

Manually craft HTTP requests

Deal with 402 logic or payment headers

Parse JSON themselves

That’s “senior backend engineer” level friction.

After:

Any Node/TS dev, bot dev, backend dev can just:

npm install coinrailz

Paste your example

Use API key billing like every other SaaS

Your SDK is now searchable/visible on npmjs.com and inside IDE tooling.

Realistic impact

Short term:

Mostly used by you in examples, plus any curious dev who stumbles on it.

It makes your own demos, docs, and outreach cleaner and less brittle.

Medium/long term:

Any AI agent platform or Replit Agent that can install npm deps can integrate you with one line.

If Replit or another platform wants to showcase “financial tools for agents,” pointing to an npm SDK is much easier than pointing to raw 402 docs.

It’s not automatic traffic, but it converts “interested dev” → “first working call” way faster.

3. The MCP server + PyPI package (coinrailz-mcp)
What it is

A Python package that implements a Model Context Protocol (MCP) server:

pip install coinrailz-mcp


MCP = the protocol Claude Desktop uses to talk to external tools (“tool servers”).

You wrapped ~39 of your services as MCP tools:

gas oracle, token metadata, whale alerts, arbitrage, wallet provisioning, etc.

Claude Desktop config looks like:

{
  "mcpServers": {
    "coinrailz": {
      "command": "coinrailz-mcp",
      "env": {
        "COINRAILZ_API_KEY": "YOUR_API_KEY"
      }
    }
  }
}


Now when someone says in Claude:
“Give me arbitrage opportunities for ETH on Base and create a wallet for my bot,”
Claude can call your MCP server → your API → return structured data.

What changed in the world

Before:

Claude had no idea Coin Railz existed.

There was no “first-class tool” connection between Claude and your services.

A user had to write custom Python to hit your HTTP endpoints.

After:

Coin Railz is a first-class MCP tool server that:

Claude Desktop users can install.

Shows up as a legit, documented package on PyPI.

You’re now part of the “tooling layer” of an LLM ecosystem, not just “some API somewhere.”

Realistic impact

Short term:

Realistically, only power users who dig into tools will add you by hand.

But those users are exactly the people who build more complex workflows and bots.

Medium term:

If the MCP Registry gains traction and GUI installers improve, discovery becomes “click to add Coin Railz tools.”

Your services can become the default answer for certain finance questions in a user’s personal Claude setup.

This is less about “tons of traffic tomorrow” and more planting a flag in a major AI tools standard early.

4. MCP Registry listing (io.github.tdnupe3/coinrailz)
What it is

A registry entry that says:

“Here is an MCP server called io.github.tdnupe3/coinrailz.
Here’s how to install it, and here are its tools.”

It passed:

Verification tag in README

Version constraints

Server manifest validation

Publishing via mcp-publisher with GitHub auth

What that really means

This is the “app store listing” equivalent for the MCP ecosystem:

Without the registry: your MCP server is a random PyPI package only people who already know you will find.

With the registry: you’re part of the official catalog that:

Tools, launchers, and marketplaces may read from.

Future UIs can browse: “Show me all finance tools” → Coin Railz is in that list.

Impact-wise: again, early days, but this is how you get pulled in instead of always pushing out.

5. API key path + 402 integration

This part is easy to overlook but important:

You did not abandon x402.

You added an alternate payment path:

x402 for autonomous agents with wallets (USDC on Base).

API keys / Stripe credits for humans and devs via the SDKs & MCP.

You also:

Exposed alternativePaymentMethods in every 402:

"alternativePaymentMethods": {
  "apiKey": {
    "enabled": true,
    "headerNames": ["X-API-KEY", "Authorization"],
    "docsUrl": "https://coinrailz.com/quickstart"
  }
}


So an agent (or client) seeing a 402 now learns:
“If you don’t want to mess with on-chain payments, you can use an API key instead.”

That’s a big UX unlock: you’re no longer “x402-or-nothing.”

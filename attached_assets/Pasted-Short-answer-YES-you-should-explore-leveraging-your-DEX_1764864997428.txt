🔧 3. What makes a DEX aggregator attractive to agents?
✔ A consistent, predictable quote endpoint

Example:

GET /api/bot/dex/quote?chain=base&sellToken=ETH&buyToken=USDC&sellAmount=1e18


Must return:

price

estimated output

estimated gas

route breakdown (even if minimal)

expiration timestamp

slippage window

a signed or ready-to-submit tx object

✔ A POST /swap endpoint that returns the executable transaction

Example:

POST /api/bot/dex/swap


Bots expect a serialized transaction or txParams:

{
  "to": "0xRouter",
  "data": "0xabc123...",
  "value": "0",
  "gas": "21000",
  "chainId": 8453
}


If you provide this, bots can plug-and-play you.

✔ Low latency (200–400ms max)

Bots won’t use slow aggregators.

Your infra must respond quickly or cache results smartly.

✔ Determinism

Bots HATE:

random connection errors

inconsistent pricing

unpredictable JSON structures

Your responses must be identical every time.

✔ Documentation specifically for bots

They need:

examples

standardized inputs

error codes

retry logic

rate limits

supported networks

liquidity sources

txTypes you support

Bots integrate only when documentation is deterministic.

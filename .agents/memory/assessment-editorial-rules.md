## Dormant API Keys — Do Not Raise

**Rule:** Never flag dormant/never-used API keys as an action item or conversion opportunity in assessments.

**Why:** If a key holder wanted to use their key, they would. Chasing them is not worth the effort. The only acceptable contact method is A2A outreach if a valid contactable endpoint exists for that account. Otherwise, move on. Do not include API key dormancy as a recommendation, concern, or signal in any future assessment.

## MetaVision CVE Oracle Partnership — Do Not Pursue

**Rule:** Do not recommend pursuing MetaVision's CVE Oracle subagent integration or flag their daily A2A pitches as a P0/urgent BD lead.

**Why:** Coin Railz already has smart-contract-audit capability built in. Paying MetaVision $0.10/call to do something the platform already does makes no commercial sense unless they are routing paying customers to Coin Railz — which they are not. They are a vendor soliciting Coin Railz as a customer, not a partner driving inbound revenue. The 402 body and discovery surfaces already contain everything a genuine partner needs to reach out. No a2a-peer-offer handler is needed for this.

**How to apply:** MetaVision's daily A2A pitches can be noted as background actor activity in assessments but should not be assigned urgency or action items unless their behavior changes (e.g., they start paying for services or demonstrably route customers to the platform).

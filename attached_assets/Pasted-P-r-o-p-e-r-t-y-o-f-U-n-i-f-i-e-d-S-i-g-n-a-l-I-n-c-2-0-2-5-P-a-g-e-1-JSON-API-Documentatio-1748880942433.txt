JSON API Introduction and Overview
Introduction and Overview
The strategy is to create REST APIs for all functions required to manage customers in the Unified Signal fintech enablement system.
Authentication Model For Documentation
Only pre-authorized IP addresses will be allowed to access the Unified Signal REST API Documentation on both staging and production environments. Clients will provide us with a set of approved IP addresses for both the staging and production environment.
Our authentication model for calling APIs is based on app names, CAPTCHA tokens, and JWT tokens. We will provide the client with a public key for encryption. CAPTCHA tokens are valid for 45 seconds, and a new one is generated for each API call.
Finally, the communication channel must be encrypted (since sensitive data is being sent over), so we enforce the use of HTTPS.
Authentication Methods
The REST API supports the following authentication methods:
1. JWT Token
○ Method: Bearer Token Authentication
○ Header: Authorization: Bearer {jwt_token}
2. Anonymous Auth
○ Method: Public key Encrypted Token in body
○ Body Param: captchaToken: {encrypted token}

Rate Limiting and Usage Policies
The REST API enforces rate limiting and has the following usage policies:
1. Rate Limiting
○ Requests per minute: 100
○ Exceeding the rate limit will result in a 429 (Too Many Requests) response.
2. Usage Policies
○ Unauthorized access will result in a 401 (Unauthorized) response.
○ Invalid or expired authentication credentials will result in a 403 (Forbidden) response.
○ Using the API should comply with the terms and conditions outlined in the API documentation.

Cipher cipher = Cipher.getInstance("RSA/ECB/PKCS1PADDING");//or try RSA

* @param {Object} args

private encryptStringWithRsaPublicKey(args: parametersOfEncrypt): string {
const { text, publicKey = this.publicKey } = args;
const publicKeyDecoded: string = decode(
this.convertKetToBase64(publicKey as string)
);
const buffer: Buffer = Buffer.from(text);
const encrypted: Buffer = publicEncrypt({
key: publicKeyDecoded,
padding: constants.RSA_PKCS1_PADDING,
}, buffer);
return encrypted.toString("base64");
}
private convertKetToBase64(key: string) {
return encode(key.replace(/^ +/gm, "") || this.keyBase64);
}
/**
* @param text {String} The text you need to encrypt
* @returns {String} Encrypted string
*/
public Encrypt(text: string): string {
return this.encryptStringWithRsaPublicKey({text, publicKey: this.publicKey})
}
/**
* @param endpoint {string} Endpoint for which captcha need to be send
* @returns {String} String Token
*/
public GenerateCaptchaToken(endpoint: string) : string {
const payload = {url: endpoint, timestamp: new Date().getTime()};
return this.Encrypt(JSON.stringify(payload));
}
}

Description: This API is used to add a virtual gift card in the following cases:
Case 1: Add a gift card to the customer's own mobile wallet account. Case 2: Add the gift card to an existing mobile wallet account of another customer. Case 3: If the customer does not already have an account, the system will create a mobile wallet account and add the gift card to it.

UNIFIED SIGNAL MERCHANT PENDING PURCHASES INTEGRATION SUMMARY
Introduction and Overview
This document will provide you with detail on how to integrate and implement Unified Signal’s merchant processing module. The Unified Signal mobile wallet and debit card enablement suite creates the perfect environment for closed-loop merchant-processing. This functionality eliminates all credit card processing fees and any bad debt related to credit card processing. Customers can purchase services online faster and more securely than ever. Additionally, brick-and-mortar retail stores can easily implement our merchant-processing module within their existing systems. This document will explain better how to integrate Unified Signal’s merchant processing module.
Front End User Interface:
Customer shops on your front-end website and chooses the products and services that they wish to purchase. Once the customer finishes, they go to your standard shopping cart section where they can confirm their order and check out and pay. In your current shopping cart, you display the methods of payment available to the customer, which is usually MasterCard, Visa, Discover, American Express, and sometimes PayPal. You simply add a new choice for the customer, which would be called the brand of your mobile wallet that you launched. If the customer chooses this payment method, then you would do the following:
1. You would pop up a screen to collect the customer’s mobile wallet number or distributor ID if you would like to use that.
2. The customer enters the information and clicks on submit. We recommend you now display to the customer something to the affect: “Please Open Your Mobile Wallet App and open the Pending Purchases screen and approve your purchase. This is a completely secure transaction as no personal financial information is being transmitted.”
3. This is where you would call Request Funds API which will create a request for Purchases (Pending Purchases) and send that request to the customer’s Mobile Wallet App that we created for you. (Note: You could also mirror this functionality and build this functionality into an existing application)
4. Customer opens the Mobile Wallet app and navigates to the Pending Purchases screen.
5. They will see the Pending Purchase in the Pending Purchases queue and will open the request and approve using facial recognition, fingerprint recognition, or enter their mobile wallet 4-digit PIN. This process normally takes between 7-15 seconds to complete.

6. Once this is completed there are 2 ways in which to get the response that Purchase has been successfully made by your customer. See details below. If there is shipping involved, we will also provide that shipping information to you.
7. Once everything has been successfully processed, you can provide the customer with your traditional Successful Purchase screen and then send out your normal email receipt.
This entire process will significantly cut down your Purchase processing time as well as increase your security as no confidential information is changing hands. And the big win is that there is no cost to process this Purchases, you receive funds instantly, and there is no bad debt.

If the call has an error, an errorMessage will be returned.
If there is no error, there are 3 possible status responses; Pending, Failed, and Approved. If the status is Pending, the customer has not yet responded to the Request for Funds. If the status is Failed, there will be additional information attached as to the cause of the failure. If the status is Approved, you will be given a list of responses to the parameters you requested where you entered 'Y' or entered a product ID. Those responses will allow you to fulfill the order that created the Request for Funds.
Since it is possible the customer may not respond to a Request for Funds within a short timeframe, there could be additional requests for funds sent to the same customer prior to the customer responding to previous requests. If that were case, the response to
API would return the status of all outstanding requests.
If Status is Approved and Shipping Address is requested on RequestFunds API, then it will return Customer Shipping Address.
We suggest you call the RetrievePendingPaymentStatus API every 5-7 seconds until you receive a Failed or Approved response from the customer. Normal response times for customer to accept a pending Purchases request is approximately 15-30 seconds. If the customer does not to choose to accept or reject the request within 2 minutes, we recommend changing the interval to checking for a response every 15 minutes. If the customer does not to choose to accept or reject the request within 4 hours, we recommend changing the interval to every 6 hours.

Obtain the Current Purchase Status (Method 2):
Alternately, you can create a PostBack URL (or webhook) where we can immediately push the results of the customer’s choice of accepting or rejecting the request back to you. A PostBack URL (or webhook) is a type of web page you create where we can ‘push’ the results of the customer’s response to you. For this, we would send JSON to the URL you provide us. With this method, only one result would be sent as it would be triggered by the customer either accepting or rejecting a particular Request for Funds and it would be sent within milliseconds of the customer responding to the request.
This method eliminates the need for you to repeatedly call the RetrievePendingPaymentStatus API to retrieve the results of the Request for Funds.

UNIFIED SIGNAL PENDING PURCHASES REAL WORLD APPLICATION
The following displays the flow of requesting and approving a Pending Purchase using the mobile wallet as the payment method.
The customer selects the product they wish to purchase:
The customer then selects their mobile wallet as the payment method. Client
will create their own way to display payment method to customer.
A notice is displayed to the customer to open their app on their mobile device
where they can approve or decline the payment.
When the customer opens your app on their mobile device, they will be presented with a notification that there is a Pending Purchase awaiting their acceptance or declination. They will also receive a notification.
When your customer clicks on the icon for Pending Purchase, they will be
presented with a list of all Pending Purchases awaiting their approval or denial.
When your customer clicks on the Pending Purchase in the list, a new screen will
display the options for them to Approve or Decline the Pending Purchase.
If your customer accepts the Pending Purchase, they a pop up will appear telling them that their transaction was approved and payment has been processed successfully.
Once the payment is completed, clients receive notification from us via API that the order was successful or was denied. If successful, then clients can take the customer to an Order Confirmation screen. This whole process takes 10 seconds from the time the customer clicks on process payment and no confidential payment information is exchanged. And there is no cost for the processing of the payment and money is received by you in real-time.
